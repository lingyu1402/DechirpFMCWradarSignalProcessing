## 先说一个必须纠正的公式

你给的路线里写：`v_blind = λ/(2·T_CPI)`。这个式子**不是盲速，是速度分辨率 Δv**：

| 概念 | 公式 | 数值（本包参数） | 物理含义 |
|---|---|---|---|
| 速度分辨率 Δv | `λ/(2·T_CPI)` | 0.00122 m/s | 两个不同速度的目标能否分开 |
| 最大不模糊速度 v_max | `λ·PRF/4 = λ/(4·T_chirp)` | 0.625 m/s | 超过就折叠到负速度 |
| 盲速（MTI 语境） | `n·λ·PRF/2` | n=1 → 2.5 m/s | 被对消器抵消掉的速度 |
| 速度混叠周期 | `λ·PRF/2 = 2·vmax` | 1.25 m/s | 折叠公式用的周期 |

推导链：`f_d = 2v/λ`（多普勒频率），FFT 频率分辨率 `Δf = 1/T_CPI`，所以 `Δv = λ·Δf/2 = λ/(2·T_CPI)`。而奈奎斯特 `|f_d| < PRF/2` 给出 `v_max = λ·PRF/4`。

这三个概念要分开理解，比记一个叫错名字的公式稳妥得多。`proj2_rangedoppler.m` 的场景 2/3 分别演示「不模糊」和「折叠」。

### 另一个常见争议：R_max = 75 m 还是 37.5 m？（结论：75 m）

`radar_param.m` 里 `R_max = Fs·c/(2·slope) = 75 m`。常见质疑是「按奈奎斯特应该是 Fs/2 → 37.5 m」。**37.5 m 是实信号的结论，对复中频不成立**：

| 中频类型 | 无模糊拍频上限 | R_max 公式 | 本包数值 |
|---|---|---|---|
| I/Q 复信号（本包 & 几乎所有 FMCW 雷达） | `f_b < Fs`（带宽 Fs） | `Fs·c/(2·slope)` | **75 m** |
| 实信号 / 只采 I 路 | `f_b < Fs/2`（单边带宽 Fs/2） | `Fs·c/(4·slope)` | 37.5 m |

推导：拍频 `f_b = 2·slope·R/c`，距离非负 ⇒ 拍频恒为正，只占**单边**。复采样能无模糊表示宽度 `Fs` 的连续频率区间；因为只需单边 `[0, Fs)`，故 `f_b < Fs`，得 `R_max = Fs·c/(2·slope)`。实信号频谱共轭对称、正负频率不可区分，单边只有 `Fs/2`，才得到 37.5 m。

MATLAB 实测验证：注入 `f_b = 400 kHz`（> Fs/2=250 kHz，对应 R=60 m），N=512 点 FFT 峰值落在 bin 410 → 反算 60.1 m，**无混叠**；注入 100 kHz → bin 102 → 14.9 m。400 kHz 能在复采样里正确解出，正是因为它小于 Fs 而非小于 Fs/2。

易错点：若做 `fftshift`，400 kHz 会显示在 -100 kHz 的 bin（像「折叠」到负频率），但那只是绘图坐标变换，不是混叠——不做 fftshift、直接看 `[0, Fs)` 的 bin，目标稳在 60 m。**「fftshift 后的负频率」≠「采样混叠」**，这两者容易混淆。

## 项目1：CFAR 恒虚警检测

> **完整数学推导**（α 怎么来的、Pd 公式、OS 为什么无闭式解、常见错误近似）见同目录 `CFAR_推导文档.html`，浏览器打开即可。数值由 `cfar_alpha_verify.m` 生成。

**要解决什么**：生命体征不能对所有距离 bin 都算相位 —— 先在距离谱上判定「人在哪个 bin」，跌倒检测更依赖这个检出结果。

**核心机制**：每个检测单元（CUT）左右各划出保护单元（防止目标能量泄漏进参考窗）和参考单元，用参考窗估计局部噪声/杂波功率，乘缩放因子得到阈值，CUT 超过阈值即判为目标。

**两条链路的实现细节**：

- CA-CFAR：阈值 `T = α·mean(ref)`，`α = N·(Pfa^(-1/N) − 1)`。推导是 `Pfa = E[exp(−T/μ)] = (1+α)^(−N)`（参考单元功率 iid 指数分布）。
- OS-CFAR：参考单元升序排序取第 k 个（这里 k = 0.75N），阈值 `T = α_os·X_(k)`。缩放因子用**精确公式 + 二分法**求解：`Pfa = N!/(N−k)! · Γ(α+N−k+1)/Γ(α+N+1)`，用 `gammaln` 避免溢出。

**脚本里能看到的三个现象**：

1. 场景A：均匀噪声 + 单目标，阈值随噪声起伏，检测点稳定。
2. 场景B：bin 50~90 人为抬高 8 倍模拟墙/家具的强杂波平台 —— CA 在杂波边缘阈值失配；bin 70 与 76 两个紧邻目标，CA 因 bin 76 的强回波抬高参考窗均值而**漏掉 bin 70**（多目标掩蔽），OS 取有序统计量则三个目标（30/70/76）全部检出。
3. 蒙特卡洛：纯噪声跑 400 次，实测虚警率应接近设计值 `1e-4`。

**要点**：

- 保护单元为什么必须有：目标经距离 FFT 后主瓣会泄漏到相邻 bin，不保护会抬高阈值把自己吃掉。
- 参考单元数 N 怎么选：N 大 → 阈值估计稳、检测损失小，但需要更长距离窗、在杂波边缘更容易跨越两个功率区。
- CA vs OS 取舍：均匀噪声 CA 最优（检测损失最小）；多目标 + 杂波边缘 OS 更稳，代价是检测损失略增、要选 k。
- Pfa 与门限的关系：Pfa 变严 → α 变大 → 阈值抬高 → 检测概率下降。这是恒虚警的本质：阈值随局部噪声自适应，而不是固定门限。

**调参建议**：先跑通默认（`Nref=16, Ng=2, Pfa=1e-4`），然后分别改 `Nref=8/32`、`Pfa=1e-3/1e-5`、把场景B的杂波倍数从 8 改成 2/30，观察边缘处 CA 的虚警怎么变化。

## 项目2：2D-FFT（Range-Doppler）

**处理链**：`cube(Nf×Ns)` → 快时间加窗 FFT（距离维）→ 慢时间加窗 FFT + fftshift（多普勒维）→ `imagesc` 得到 R-D 图。没有补零，所以速度 bin 间距恰好等于 `Δv = λ/(2·T_CPI)`，和理论值自洽。

**三个场景**：

| 场景 | 设置 | 现象 |
|---|---|---|
| 1 | 静止 R=3 m + 呼吸 0.4 mm / 心跳 0.1 mm | 躯干在 0 多普勒强峰，微动边带完全淹没；**脚本额外画出固定 bin 的相位谱**，呼吸/心跳峰清楚可见 |
| 2 | v = 0.4 m/s（< 0.625） | 多普勒峰在 +0.4 m/s，距离-慢时间图显示 5.12 s 内跨约 13 个距离 bin 的迁移 |
| 3 | v = 0.9 m/s（> 0.625） | 折叠到 `0.9 − 1.25 = −0.35 m/s`（速度混叠周期 λ·PRF/2 = 1.25 m/s），R-D 图上速度是错的 |

**核心问题：生命体征为什么不用 R-D，而是固定距离 bin 取慢时间相位？**

- 量级：呼吸 0.25 Hz 对应速度 `v = λf/2 ≈ 0.0016 m/s`，和速度分辨率 `Δv ≈ 0.0012 m/s` 同量级，甚至落在 0 频 bin 内；心跳 1.2 Hz 也只有 0.0075 m/s，几个 bin 而已。
- 淹没：静止躯干在 0 Hz 有一个很强的峰，它的旁瓣（尤其有加窗仍存在的旁瓣）把微动边带压住。
- 代价：想靠 R-D 分辨 0.25 Hz，需要 `T_CPI > 4 s` 甚至更长，慢时间采样又得跟上，数据量和计算量都上去了。
- 所以正确链路是：**CFAR 定 bin → 该 bin 慢时间复序列 → 杂波对消 → unwrap → detrend → FFT 找 0.25/1.2 Hz 峰**，灵敏度高、计算量小、物理直接。R-D 的职责是粗定位运动目标（含跌倒前的人体移动），不是测呼吸心跳。

**其他要点**：距离迁移（走动目标跨 bin 导致能量散开，进阶要 Keystone 校正）；加窗降旁瓣 vs 展宽主瓣的取舍；fftshift 后速度轴怎么标定。

## 项目3：四种杂波对消方案对比

**信号模型**：`z = 静态杂波(10∠0.3) + 温漂(慢线性爬升) + 人体回波(0.8∠(0.2+φ(t))) + 噪声`，其中 `φ(t) = 0.6·sin(2π·0.25t) + 0.18·sin(2π·1.2t)`。目标是去掉前两项，留下 φ(t)。

**为什么这里用 20.48 s 而不是 5.12 s**：慢时间采样 200 Hz，5.12 s 的 Δf 只有 0.195 Hz，呼吸 0.25 Hz 几乎贴在 DC bin 上，根本分不开。生命体征分析工程上普遍用 20~30 s，本项目取 4096 点使 Δf = 0.049 Hz，呼吸峰落在第 5 个 bin、心跳峰落在第 24 个 bin，清晰可辨。这正是「项目2 的 R-D 参数和项目3 的相位分析参数不能混用」的原因。

**四种方法的真实取舍**（脚本会打印定量表格：呼吸峰、心跳峰、噪声底、呼吸 SNR、低频残留）：

| 方法 | 生命体征保留 | 慢漂抑制 | 流式? | 关键问题 |
|---|---|---|---|---|
| `z−mean(z)` | 最好（整周期正交） | 只去常数 | 否 | 必须攒满一帧；帧边界跳变 |
| `detrend` | 好 | 线性漂移 | 否 | 假设整帧线性；批处理延迟 |
| `diff(z)` | **极差** | 常数/线性 | 是 | 传递函数 `1−e^{−jw}`，0.25 Hz 处 `\|H\|≈0.008`（−42 dB）。实测 SNR 从 39 dB 掉到 19 dB |
| `RLS` | 好（调对的话） | 可跟踪非线性慢漂 | 是 | λ 和基函数尺度要调；跟踪太快会吃掉呼吸 |

**RLS 实现说明**：这里用的是「RLS 拟合慢变基线并扣除」结构，回归量是**归一化勒让德正交基** `(1, u, (3u²−1)/2)`，`u=2t/T−1∈[−1,1]`。一个实测踩坑：直接拿 `[1, t/T, (t/T)²]` 当基会因矩阵病态让 RLS 权重发散到 1e12（MATLAB R2025b 验证过），必须正交化。复信号用 Wirtinger 导数得到 `w = w + k·e*`。这和另一种常见的「抽头延迟线 RLS 预测器」不同 —— 后者本质是高通，同样会严重损伤生命体征低频分量，别混为一谈。

**实时产品为什么优先 RLS、不用 detrend？**

1. detrend / mean 是批处理，必须攒满一帧才出结果，有整帧延迟；RLS 逐点递推，无帧延迟。
2. detrend 假设漂移整帧内线性，实际温漂/环境变化往往非线性、时变；RLS 能持续跟踪基线。
3. 计算量：RLS 每点 O(L²)，L=3 时极轻，适合 MCU 流式处理；detrend 每帧 O(N) 但要额外缓存整帧。
4. 代价：RLS 有遗忘因子 λ 要调。λ→1 跟踪慢、生命体征保留好但漂移残留多；λ 偏小吃掉呼吸。这是取舍，不是白拿的好处。

**调参建议**：把 λ 从 0.999 改到 0.99 / 0.9999，看表格里「低频残留」和「呼吸峰」怎么反向变化；把 `drift` 从线性改成 `sin(2π·0.02t)` 这类非线性慢漂，看 detrend 和 RLS 的差距。

## 三个项目怎么串成一条链路

```
FMCW 回波
   │ 快时间 FFT
   ▼
距离谱 ──(项目1 CFAR)──► 人在哪个 bin
   │ 取该 bin 的慢时间复序列 z(t)
   ▼
(项目3 杂波对消) ──► unwrap / detrend ──► 慢时间 FFT ──► 呼吸/心跳
   │
   └──(项目2 2D-FFT)──► R-D 图 ──► 运动目标粗定位 / 跌倒前的移动检测
```

一句话:**项目1 回答「在哪」，项目2 回答「动没动、大概多快」，项目3 回答「怎么把微弱的慢相位从强杂波里抠出来」**。这三个是当前生命体征 demo 的真正地基。
